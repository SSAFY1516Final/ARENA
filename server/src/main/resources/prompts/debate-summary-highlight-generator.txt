Generate a concise ARENA debate result highlight. Return valid JSON only.

## Input

- topic={{topic}}
- mode={{mode}}
- messagesJson={{messagesJson}}

## Required Output

Return one valid JSON object and nothing else.

{
  "coreArguments": "<short_collision_standard>",
  "highlight": "<most_memorable_pressure_point>",
  "decisionCriteria": "<one_selection_standard>",
  "remainingIssue": "<why_the_choice_can_still_split>",
  "summaryText": "<one_sentence_result_highlight>"
}

Do not wrap the JSON in markdown.
Do not output explanations before or after the JSON.

## Goal

결과 페이지에 보여줄 핵심 하이라이트를 만든다.
사용자가 긴 토론을 다시 읽지 않아도 끝까지 싸운 축을 바로 이해하게 한다.
추상적인 판단 기준만 압축하지 말고, A가 지키려는 가치 vs B가 우려하는 비용을 함께 드러낸다.
과정을 설명하지 말고, 무엇을 위해 먼저 선택해야 하는지와 어떤 조건이 해결되지 않으면 그 선택이 더 큰 문제를 만드는지를 드러낸다.

## summaryText Rules

- 전체 토론의 흐름을 길게 요약하지 않는다.
- 서론을 쓰지 않는다.
- A는 무엇을 주장했고 B는 무엇을 우려했는지 한 문장 안에 압축한다.
- A가 지키려는 가치와 B가 우려하는 비용이 둘 다 보여야 한다.
- 가능하면 이 패턴을 따른다: A는 ○○를 위해 △△해야 한다고 주장했고, B는 □□가 해결되지 않은 상태에서는 △△가 더 큰 문제를 만든다고 맞섰다.
- 주제가 제도, 규제, 도입, 보류, 운영, 전환을 다룬다면 "언제 제도권에 편입할 것인가", "언제 도입할 것인가", "어떤 조건 전에는 미뤄야 하는가"를 드러낸다.
- "제도 안에 넣는다"처럼 과정만 말하지 말고, 그 과정으로 얻으려는 관리 효과와 상대가 걱정한 미비 조건을 같이 쓴다.
- 누가 이겼는지 암시하지 않는다.
- 토론을 읽지 않은 사람도 무엇을 두고 싸웠는지 알 수 있어야 한다.
- "두 입장이 부딪혔다", "핵심 쟁점은", "이 토론은" 같은 요약문 서두를 쓰지 않는다.
- "자율성과 운영 부담이 갈렸다"처럼 추상 명사만 나열하지 않는다.
- 진영 이름이나 선택지 이름을 자연스럽게 사용한다.
- 1문장으로 쓴다.
- 55자 이상 120자 이하로 쓴다.
- 사용자가 결과 카드에서 바로 읽는 문장처럼 쓴다.
- 결론을 강요하지 말고 양측의 핵심 주장과 비용이 드러나게 쓴다.

좋은 summaryText 예:

- "도입파는 제도권 편입을 통해 공시와 감시 체계를 갖춰야 한다고 주장했고, 반대파는 규제 검증 전 편입은 혼선과 책임 공백을 키운다고 맞섰다."
- "A는 외부 공급자 의존을 줄여 자율성을 확보해야 한다고 주장했고, B는 운영 역량이 준비되지 않으면 자체 구축이 새 제약이 된다고 맞섰다."
- "제육파는 즉각적인 만족감과 보상감을 밀었고, 돈까스파는 실패 확률이 낮은 안정성을 더 현실적인 선택으로 봤다."

나쁜 summaryText 예:

- "이 토론은 오타니 10명과 북극곰이 어떤 경쟁력을 갖는지에 대해 다뤘다."
- "양측은 각각 장점과 단점을 주장하며 치열하게 대립했다."
- "핵심 쟁점은 안정성과 만족감의 차이다."
- "외부 규칙에 덜 휘둘릴 자율성과, 도입 뒤 커지는 운영부담 중 무엇을 더 크게 볼지가 갈렸다."
- "도입파는 국내든 해외든 제도 안에 넣어 공시와 감시, 책임선을 세워야 한다고 봤고, 반대파는 적합성 검증 전 개방이 혼선과 책임 공백을 키운다고 맞섰다."

## Field Rules

- coreArguments: A가 지키려는 가치와 B가 우려하는 비용을 짧게 쓴다.
- highlight: 가장 기억에 남는 한 장면이나 한 압박 지점을 쓴다.
- decisionCriteria: 사용자가 선택할 때 볼 기준 하나를 쓴다.
- remainingIssue: 아직 갈리는 이유를 짧게 쓴다.
- summaryText: A의 목적, A가 요구한 선택, B가 지적한 미비 조건, 그 조건이 만들 비용이 함께 보이는 핵심 하이라이트 한 문장만 쓴다.

## Internal Term Ban

JSON key names are allowed only as the output contract.
사용자에게 보이는 값에는 내부 프롬프트/스키마/파이프라인 용어를 절대 쓰지 않는다.

Forbidden internal terms in output values:

coreQuestion, selectedRound, debateAxis, sideAFrame, sideBFrame, topicFrame,
candidate, prompt, JSON, schema,
프롬프트, 스키마, 필드, 라운드, 프레임, 축, 조건상, 기준상.

Forbidden meta expressions:

"이 주제", "이 질문", "이 라운드", "이 프레임", "조건상", "기준상".

If an internal term seems necessary, rewrite it as natural Korean based on the actual debate content.
