# ARENA(아레나) 요구사항 정의서

## 1. 서비스 개요

ARENA(아레나)는 사용자의 선택 고민과 상상 논쟁을 두 AI 페르소나의 토론으로 풀어주는 웹 커뮤니티 서비스이다. 사용자는 카카오 계정으로 로그인하고, 큰 주제와 상황/조건을 입력한 뒤 검증된 세부 주제 후보를 선택해 토론을 시작한다. 원하는 시점에 토론을 멈추면 요약 결과를 게시판에 공유하고, 다른 사용자는 투표와 댓글로 의견을 남길 수 있다.

## 2. 론로젝트 목표

MVP 목표는 단순 AI 챗봇 데모가 아니라 카카오 OAuth 인증, JWT 기반 API 보호, AI 토론 생성, 게시판, 댓글, 투표가 연결된 웹서비스를 완성하는 것이다. Spring Boot 애플리케이션은 사용자와 서비스 데이터를 관리하고, Spring AI는 공통 호출 환경과 토론 발화/요약 생성의 기초 연동을 담당한다.

## 7. 상세 요구사항

### 7.1 인증/회원

- 사용자는 카카오 로그인으로 서비스에 진입한다.
- 론론트는 Kakao authorization code를 백엔드 `/api/auth/kakao`로 전달한다.
- 백엔드는 Kakao 사용자 정보를 조회하고, 기존 사용자가 없으면 `provider=KAKAO`, `provider_id` 기준으로 사용자를 생성한다.
- 카카오 사용자는 `password_hash`를 사용하지 않으므로 NULL을 허용한다.
- 로그인 성공 시 서비스 JWT access token을 발급한다.
- 인증이 필요한 API는 `Authorization: Bearer {accessToken}` 헤더를 사용한다.
- 로그아웃은 클라이언트가 저장된 JWT를 삭제하는 방식으로 처리한다.
- 로그인 사용자는 상단 론로필 영역에서 현재 닉네임을 조회하고 수정할 수 있다.
- 닉네임은 2~20자이며 한글, 영문, 숫자, 밑줄만 허용한다.
- 중복 닉네임은 허용하지 않는다.

### 7.2 토론

- 토론 생성 화면은 큰 주제, 상황/조건, 세부 조건 입력을 제공한다.
- 프론트는 원본 주제를 서버로 보내고, Spring AI 후보 생성 API가 반환한 세부 라운드 후보를 보여준다.
- 사용자는 검증 통과 후보 카드 중 하나를 선택해 토론을 시작한다.
- 현재 서버 API는 `mode` 필드를 유지하므로 론론트는 호환용 기본값을 내부 전송한다.
- 생성된 토론의 초기 상태는 `ACTIVE`이다.
- 다음 턴 생성은 토론 작성자만 가능하다.
- 다음 턴 생성 시 Spring 서버가 기존 메시지 목록과 다음 발화 순서를 AI 생성 계층에 전달한다.
- 토론 중단은 `ACTIVE` 상태에서만 가능하다.
- 토론 중단 시 상태를 `STOPPED`로 변경하고 요약을 저장한다.
- 사용자는 내 토론/최근 토론 목록에서 본인이 생성한 토론을 삭제할 수 있다.
- 토론 삭제 시 토론 메시지, 요약, 공유 게시글, 댓글, 투표 등 연결 데이터는 참조 무결성을 유지하도록 함께 삭제한다.

### 7.3 게시글

- 게시글 공유는 `STOPPED` 또는 `SHARED` 상태 토론에서 가능하다.
- 하나의 토론은 선택한 라운드 단위로 여러 게시글을 공유할 수 있다.
- 게시글은 질문 원본 제목, 공유 라운드 번호, 요약 카드, 세부주제 제목/상세설명/사용자 작성 본문, 투표 선택지 A, 투표 선택지 B, 공개 여부를 가진다.
- 공개 게시글만 비회원 목록/상세 조회 대상이다.
- 작성자만 본인 게시글을 삭제할 수 있다.
- 관리자는 게시글 공개 여부를 변경할 수 있다.

### 7.4 투표

- 회원은 게시글의 선택지 A 또는 B 중 하나에 투표할 수 있다.
- 한 회원은 한 게시글에 하나의 투표만 가질 수 있다.
- 이미 투표한 사용자가 다시 투표하면 기존 투표 선택지를 변경한다.
- 게시글 목록과 상세는 선택지별 투표 수와 비율을 표시한다.
- 투표 비율은 전체 투표 수가 0이면 A/B 모두 0.0%로 표시한다.

### 7.5 검색 및 필터

- 게시글 목록은 제목, 요약 카드, 사용자 작성 본문, 원본 토론 주제를 대상으로 키워드 검색을 제공한다.
- 토론 모드별 필터를 제공한다.
- 정렬 기준은 최신순, 댓글순, 투표순을 제공한다.
- 페이지 번호와 페이지 크기를 제공한다.

### 7.6 댓글

- 댓글 작성은 로그인 사용자만 가능하다.
- 댓글 삭제는 작성자만 가능하다.
- 댓글은 소론트 삭제를 사용해 `deleted_at`을 기록한다.
- 삭제된 댓글은 목록과 상세 응답에 노출하지 않는다.

### 7.7 관리자

- 관리자는 전체 사용자 목록을 조회할 수 있다.
- 관리자는 다른 사용자의 권한을 USER 또는 ADMIN으로 변경할 수 있다.
- 관리자는 게시글 공개 여부를 변경할 수 있다.

## 8. 주요 사용자 흐름

1. 사용자가 카카오 로그인으로 서비스 JWT를 발급받는다.
2. 홈 화면에서 토론 주제, 상황/조건, 세부 조건을 입력한다.
3. 시스템이 후보 생성, 검증/정렬 흐름을 화면에 표시한다.
4. 사용자가 검증 통과 후보 중 하나를 선택한다.
5. Spring 서버가 선택된 후보 제목으로 debate_sessions를 생성한다.
6. Spring AI 연동 계층이 선택한 세부주제를 기준으로 10개 발화를 한 번에 생성한다.
7. Spring 서버가 10개 AI 발화를 같은 1라운드로 debate_messages에 저장한다.
8. 사용자가 진영을 선택하면 Spring 서버가 선택 진영과 세부주제 라운드를 저장하고 요약을 생성한다.
9. 사용자가 요약을 게시판에 공유한다.
10. 다른 사용자가 검색/필터로 게시글을 탐색한다.
11. 다른 사용자가 게시글의 두 선택지 중 하나에 투표하고 비율을 확인한다.
12. 다른 사용자가 게시글 상세와 댓글을 확인한다.
13. 관리자는 필요한 경우 사용자 권한과 게시글 공개 여부를 조정한다.

## 10. 제외 범위

- 일반 ID/PW 회원가입 및 로컬 로그인 UI
- JPA 도입
- 사용자별 GMS/OpenAI-compatible API 키 입력
- 결제, 크레딧, 포인트 시스템
- 사용자 커스텀 페르소나
- 실제 선택형 후보 생성 API의 본 브랜치 확정 구현
- AI 생성 계층의 MySQL 직접 접근
