# ARENA 프론트 서비스형 리디자인 스펙

## 목표

현재 프론트는 기능 연결은 되어 있지만, 로그인/새 토론 화면이 홍보성 히어로와 샘플 카드 중심이라 실제 서비스보다 목업처럼 보인다. 1차 개선 목표는 B-2안 기준으로 `AI 토론방 중심 서비스`처럼 보이게 만드는 것이다.

핵심 방향은 다음과 같다.

- AI 토론 생성과 진행 경험을 첫 화면의 중심으로 둔다.
- 큰 장식, 과한 샘플 카드, 랜딩 페이지식 문구를 줄인다.
- 사용자가 실제로 조작할 수 있는 입력, 상태, 액션을 화면 위계의 중심에 둔다.
- 게시판/투표 흐름은 보조 신호로 노출해 토론 결과가 커뮤니티로 이어진다는 느낌을 준다.

## 화면별 설계

### `/auth`

카카오 로그인 진입 화면이다. 현재처럼 큰 홍보성 문구와 장식성 제품 카드가 중심이 되지 않도록 줄인다.

- 좌측 또는 상단에는 짧은 서비스 정의와 카카오 로그인 버튼을 둔다.
- 문구는 "AI 토론을 바로 시작하세요" 수준으로 간결하게 유지한다.
- 보조 영역에는 실제 토론방 UI 일부를 축소해 보여준다.
- 카카오 REST API 키가 없을 때의 안내 문구는 유지하되, 화면 전체를 설명문처럼 만들지 않는다.

### `/new`

로그인 후 핵심 작업 시작점이다. B-2안의 `토론 워크스페이스`를 구현한다.

- 좌측 좁은 패널에 토론 모드, 주제 입력, 토론 시작 버튼을 배치한다.
- 중앙에는 새 토론을 시작하기 전에도 빈 미리보기 또는 최근 토론 흐름을 보여준다.
- 하단에는 최근 공유된 토론, 투표 진행 중인 게시글 같은 커뮤니티 신호를 작게 노출한다.
- 단, 게시판 영역이 주인공이 되지 않도록 카드 수와 시각적 강도를 제한한다.

### `/debates/:debateId`

토론 진행 화면이다. 토론 로그를 중심에 두고, 상태와 액션은 보조 패널로 정리한다.

- 중앙은 토론 메시지 로그를 넓게 사용한다.
- 우측에는 발화 수, 상태, 핵심 쟁점 도달 여부, 요약/공유 액션을 작게 배치한다.
- 다음 발화, 종료, 공유 버튼은 사용자가 지금 할 수 있는 액션이 명확히 보이도록 정리한다.
- 빈 토론 상태는 샘플처럼 보이지 않도록 "첫 발화 생성" 액션을 중심으로 안내한다.

### `/posts`

공유된 토론 목록 화면이다. 1차 리디자인에서는 API 호출, 검색 조건, 라우팅은 유지하고 `/new`와 `/debates/:id`의 톤에 맞춰 시각 구조만 정리한다.

- 검색/필터 영역은 도구처럼 보이게 간결하게 유지한다.
- 게시글 카드는 제목, 모드, 댓글/투표 상태가 빠르게 스캔되도록 정리한다.
- 빈 상태는 데모 데이터가 없을 때도 자연스럽게 보이도록 "아직 공유된 토론이 없습니다"에 가까운 안내로 조정한다.

## 디자인 원칙

- 전체 톤은 SaaS/운영 도구처럼 차분하고 기능 중심으로 둔다.
- 큰 히어로 섹션, 과한 장식 배경, 제품 소개식 문장을 줄인다.
- 카드 안에 카드를 중첩하지 않는다.
- 버튼은 명확한 액션에만 사용하고, 상태 정보는 태그/텍스트/작은 패널로 표현한다.
- 모바일에서는 좌측 패널, 중앙 토론 영역, 보조 신호가 순서대로 쌓이도록 한다.
- 텍스트가 버튼이나 카드 안에서 넘치지 않게 고정 높이와 responsive grid를 사용한다.

## 구현 범위

1차 구현 범위는 프론트 디자인과 화면 구조 개선이다.

- `AuthView.vue`
- `HomeView.vue`
- `DebateRoomView.vue`
- `PostListView.vue`
- `AppNav.vue`
- `client/src/styles/base.css`

API 계약, 백엔드 인증 흐름, Spring AI 파이프라인은 이번 작업에서 변경하지 않는다.

## 테스트 기준

- `npm test -- --run` 통과
- `npm run build` 통과
- 로컬 브라우저에서 `/auth`, `/new`, `/debates`, `/posts` 기본 렌더링 확인
- 로그인 토큰이 있을 때 `/new`와 `/debates/:id` 흐름이 깨지지 않는지 확인
- 모바일 폭에서 주요 텍스트와 버튼이 겹치지 않는지 확인
